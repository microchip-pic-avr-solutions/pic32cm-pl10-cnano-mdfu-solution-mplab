# Microchip Device Firmware Update (MDFU) Bootloader Solution for PIC32CM-PL10 Curiosity Nano Evaluation Kit

## Project Overview

This repository provides an optimized MDFU bootloader client for the PIC32CM-PL10 Curiosity Nano. It shows firmware update workflows using the MDFU Protocol over Universal Asynchronous Receiver/Transmitter (UART), Serial Peripheral Interface (SPI) and Inter-Integrated Circuit (I<sup>2</sup>C) interfaces. All code is standalone, containing required drivers generated via MPLAB® Harmony 3 but Harmony is **not** mandatory for operation.

- [Microchip 32-bit MCUs](https://www.microchip.com/design-centers/32-bit)
- [Microchip 32-bit MPUs](https://www.microchip.com/design-centers/32-bit-mpus)
- [Microchip MPLAB® X IDE](https://www.microchip.com/mplab/mplab-x-ide)
- [Microchip MPLAB® Harmony](https://www.microchip.com/mplab/mplab-harmony)

**Included Projects**
- MDFU Bootloader over UART, SPI, I<sup>2</sup>C
- Example test applications (LED blink, console output) for each interface

## Bootloader & Application Features

**Bootloader Features (UART/SPI/I<sup>2</sup>C):**
MDFU
- MDFU Protocol file transfer (UART, SPI and I<sup>2</sup>C) 
- CRC-32 via the Direct Memory Access (DMA) peripheral
- Software re-entry via the RAM region
- LED status indicator

> **Note:** This content does not require MPLAB® Harmony 3 and uses custom start-up code and linker script that is not generated by Harmony. Make sure this logic is not overwritten if the user intends to generate new code using Harmony.

**Application Features (UART/SPI/I<sup>2</sup>C):**
- Console output and LED blink using timer interrupt
- Bootloader mode re-entry by switch press 
- Default application image for direct flashing (`PL10_App_UART.img` or `PL10_App_SPI.img` or `PL10_App_I2C.img`)

> **Note:** A default application image has been generated and included in the repo for testing purposes. If the user does not intend to build the image using the steps below, the default test image can be used for testing the client update logic.

## Getting Started & Operation

### General Steps

1. Open MPLAB® X IDE.
2. Open the desired bootloader project (`/Bootloader_UART...`).
    - Open the bootloader project by navigating to `File>Open Project...` and select the bootloader project from the file system navigator, `<repository path>/Bootloader_UART/<bootloader_project_name>.X`
3. Set bootloader project as main, clean/build, and program the device.
    - In the **Projects** tab, right click the Bootloader project folder and select *Set as Main Project*
    - From the **Projects** tab, right click again the Bootloader project folder and select *Clean and Build*
    - Right click the Bootloader project folder again and select *Make and Program Device*
    - The bootloader will indicate that it is running and ready to receive an image by lighting the on-board LED
4. Open the example application project (`/Application_UART...`), clean/build.
    - Open the application project by navigating to `File>Open Project...` and select the application project from the file system navigator: `<repository path>/Application_UART/<application_project_name>.X`
    - Navigate to the Project Properties, select the **Building** tab, and enable the `Execute this line after build` option
    - From the **Projects** tab, right click the Application project folder again and select *Clean and Build*
5. Edit and run the update script (`run.bat`/`run.sh`) for the user platform, setting the correct port/interface below.
    - Open the `<repository path>/Application_UART/<application_project_name>.X> > run.bat`on Windows or the `run.sh` on Mac or Linux
    - In MPLAB® X IDE, this file can be found under the **Important Files** tab in the project

> **Note:** This process will execute the `pymdfu` update command through an MPLAB® X console and print the output within IDE. If the user does not have access to the Python environment within MPLAB® X, the user can copy the command from the script into any terminal with access to the `pymdfu` Python tool.

## Debugging Tips
- Useful `pymdfu` commands
```
$ > pymdfu -V
pymdfu version 2.5.1.9
MDFU protocol version 1.2.0

$ > pymdfu update --tool serial --port COM3 --baudrate 115200 --image PL10_App_UART.img
Upgrade finished successfully
```

- Adding the CLI flag -v debug at the end of the pymdfu command will enable debug logging for the Python tool, allowing the user to see the data transfers in more detail

- The user can see the program print statements by opening the MPLAB® Data Visualizer and selecting the Display as text in terminal button on the Curiosity Nano's port name

Data Visualizer Settings:

- Baud rate: 115200
- Char Length: 8
- Parity Bit: None
- Stop Bits: 1
- DTR: Enabled
- RTS: Enabled

**General Tips:**
- Use the MPLAB® Data Visualizer to confirm port and monitor serial output
- On-board LED indicates the bootloader status; LED blinks at application entry
- Press the nano switch to re-enter Bootloader mode and Re-initiate the update
